# 测试规范

## 覆盖率口径

- 分母＝`src/KuaiJi` 手写代码的可执行行。`Migrations/`（EF 生成的 `.Designer.cs` 与 `ModelSnapshot`，
  占 35,798 行＝全部可执行行的 59％）**不计入**：迁移能不能建库由 CI 的「迁移脚本可执行性」job
  在干净 PostgreSQL 上跑 `dotnet ef database update` 来保证，给生成代码逐行写断言不产生任何防护力。
- 前端与 `ui/src/apis-gen` 不在本轮范围内。
- 目标：手写代码行覆盖 95％。

## 两种装置

| 装置 | 用途 | 要点 |
| --- | --- | --- |
| `src/KuaiJi.Tests/Support/SqliteTestContext.cs` | 应用服务与领域层单测 | 内存 SQLite + `EnsureCreated`，复用生产 `AppDbContext` 映射；不起宿主 |
| `src/KuaiJi.Tests/Support/ApiTestFactory.cs` | Controller / 端到端 HTTP | 跑真实 `Program.cs` 组合根（认证、限流、Problem Details、MediatR 全生效），只把数据库换成 SQLite |

`ApiTestFactory` 的两个坑，改动它前先读懂：

1. 配置必须走**环境变量**（它的静态构造函数）。`Program.cs` 用 `WebApplicationBuilder` 建配置，
   WAF 的 `ConfigureAppConfiguration` 注不进去；而 `AddEnvironmentVariables()` 是唯一定能盖过
   `appsettings*.json` 的入口。否则本机有 `appsettings.Local.json`、CI 没有，测试只在其中一边能起。
2. 覆盖 DbContext 注册前必须**先摘掉生产描述符**（`AppDbContext` 与所有 `DbContextOptions`）。
   只追加一条 `AddDbContext` 会让 EF 抛「Only a single database provider can be registered」。

服务层连续调用多个服务时记得 `_db.DetachAll()`：生产仓储的读一律 `AsNoTracking`，同一上下文里
前一次留下的被跟踪实例会和后一次的 `Remove`/`Update` 撞主键。

## Controller 测试的写法

用 `src/KuaiJi.Tests/Api/ApiHarness.cs`（每类一个实例＝每类一套独立库），它把 `ApiTestFactory`、
带令牌的 `HttpClient`、「经 POST /AccountSets 建账套」「直写科目」三件事包好；一个用例一个账套，互不干扰。
样板见 `Api/VouchersApiTests.cs`（生命周期 + 日期绑定 + 回收站 + PDF）与 `Api/AccountsApiTests.cs`
（编码方案位数与级次 + 末级过滤 + 删除保护 + 期初汇总 + 导出↔导入回环）。

踩过的坑，照抄样板即可避开：

- 令牌里的 `displayName` 会被制单/审核端点当人名落库，断言人名就是 `ApiHarness.TokenDisplayName`。
- `await client.GetFromJsonAsync<T>()!` 的 `!` 只作用在 `Task` 上，要写成 `(await …)!`。
- 手工构造 JSON 请求体用 `new StringContent(body, Encoding.UTF8, "application/json")`，
  两参数重载会被解析成 `MediaTypeHeaderValue` 而编译不过。
- `Assert.Contains(子串, 集合)` 比的是元素相等，不是包含关系；要在集合里找子串用
  `Assert.Contains(集合, x => x.Contains(子串))`。
- 提交空 `MultipartFormDataContent`（连 file 段都没有）根本进不到控制器，框架先给 4xx；
  要命中控制器的「请选择文件」文案必须带一个 0 字节的 file 段。
- 内容不是 Excel 的上传件由读取器包装成业务异常 → 400 友好文案，不是 500；断言按这个来。
- 凭证详情端点不按软删过滤（回收站点开详情依赖这条口径），列表才按 `deleted` 分流。

## 什么算「有意义的用例」

1. 断言业务结果：金额数字、凭证状态流转、账套期间指针、报错中文文案——至少命中一项。
   只断言 HTTP 200 或「没抛异常」不算。
2. 断言必须能失败：新增用例后做一次变异抽查，把生产代码改坏一行，用例要变红；打不红的删掉重写。
3. 禁止刷覆盖率：不允许空断言、`Assert.True(true)`、纯为覆盖行数的 DTO/映射调用。
4. 用例名＝`场景_条件_期望`；注释写领域依据（AGENTS.md「领域须知」那批规则就是用例清单：
   只统计已过账凭证、结转先于结账、区间归一到自然月、借-贷净额口径、新旧准则编码兼容）。
5. 一个用例只验一件事，失败信息要能直接指出是哪条业务规则破了。

## 命令

```powershell
# 全量测试
dotnet test src/KuaiJi.Tests/KuaiJi.Tests.csproj

# 带覆盖率（生成 .coverage/<guid>/coverage.cobertura.xml）
dotnet test src/KuaiJi.Tests/KuaiJi.Tests.csproj --collect:"XPlat Code Coverage" --settings coverlet.runsettings --results-directory .coverage
node scripts/coverage-report.mjs          # 总覆盖率 + 按模块 + 未覆盖行数 TOP 榜
```

并行开发时每个改动者用自己的一份工作副本（`tar -cf - --exclude=bin --exclude=obj src | ...`），
否则两个 `dotnet test` 会抢 `KuaiJi.exe` 文件锁报 MSB3021/MSB3027。
