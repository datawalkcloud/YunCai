# 部署上线说明

> 目标形态：一台自有云服务器 + Docker Compose。三个容器：`web`（nginx 托管前端并反代 `/api`）、`api`（ASP.NET Core）、`db`（PostgreSQL）。
> `api` 不映射宿主机端口，外部只能通过 nginx 访问——这是登录限流按真实来源 IP 生效的前提。

## 一、首次部署

```bash
git clone <仓库地址> yuncai && cd yuncai
cp .env.example .env
vim .env                     # 必填：YUNCAI_DB_PASSWORD、YUNCAI_JWT_KEY、YUNCAI_ADMIN_PASSWORD
                             # 生成随机密钥：openssl rand -base64 48 | tr -d '/+='
docker compose up -d --build
docker compose exec web wget -qO- http://localhost/          # 前端可访问
docker compose exec api wget -qO- http://localhost:8080/health   # 后端健康（应为 Healthy）
```

首次启动需要创建初始管理员与默认账套：把 `.env` 里 `YUNCAI_SEED_ENABLED` 置为 `true`，`docker compose up -d` 让 `migrate` 容器跑一次，登录后**立即改回 `false`** 再 `up -d`。
若忘记关闭，重启时因用户表非空不会重复创建，但日志会暴露口令来源，不留开关更干净。

## 二、日常发布

### 方式 A：CI 构建镜像（推荐）

[`.github/workflows/release-image.yml`](../.github/workflows/release-image.yml) 在 push 到 `master`、打 `v*` 标签或手动触发时，构建 `api` / `web` 两个镜像并推送到阿里云容器镜像服务 ACR。

GitHub 仓库需要配置：

| 类型 | 名称 | 说明 |
| --- | --- | --- |
| Variables 或 Secrets | `ACR_REGISTRY` | 例 `registry.cn-hangzhou.aliyuncs.com`（企业版用你的专属域名）；Variables 优先，未配置则回退到 Secrets |
| Variables 或 Secrets | `ACR_NAMESPACE` | ACR 命名空间，同上 |
| Secrets | `ACR_USERNAME` / `ACR_PASSWORD` | ACR 访问凭证（控制台「访问凭证」里设置） |

ACR 中需预先创建 `yuncai-api`、`yuncai-web` 两个仓库。标签规则：`master` → `master` + `latest`；`v1.2.3` → `1.2.3` + `1.2` + `latest`；每次构建另带 `sha-<短哈希>`，回滚时按它拉旧镜像。

服务器 `.env` 增加：

```bash
ACR_REGISTRY=registry.cn-hangzhou.aliyuncs.com
ACR_NAMESPACE=你的命名空间
YUNCAI_IMAGE_TAG=latest        # 回滚时改成具体版本号或 sha-xxxxxxx
```

发布：

```bash
docker compose -f docker-compose.yml -f docker-compose.acr.yml pull
docker compose -f docker-compose.yml -f docker-compose.acr.yml up -d
curl -s http://localhost/health
```

镜像只构建 `linux/amd64`；服务器是 ARM 时把工作流里的 `platforms` 改成 `linux/arm64`（或两者都加）。

### 方式 B：服务器本地构建

```bash
git pull
docker compose build                      # 前端 + 后端镜像
docker compose up -d                      # migrate 容器先执行 --migrate-only，成功后才拉起 api
curl -s http://localhost/health           # 或浏览器打开站点
```

`migrate` 是一次性任务：迁移失败会让 `api` 停在等待状态而不是带着旧表结构提供服务。

## 三、配置项

生产配置全部走环境变量（`__` 表示层级），不需要 `appsettings.Local.json`（该文件仅供本机开发，且已被 `.gitignore` 排除）。

| 环境变量 | 说明 |
| --- | --- |
| `ConnectionStrings__DefaultConnection` | PostgreSQL 连接串，缺失时进程启动即失败 |
| `Jwt__Key` | JWT HMAC 签名密钥，至少 32 位随机串；缺失或过短启动即失败 |
| `Jwt__ExpireMinutes` | 令牌有效期，默认 120 分钟，当前无刷新令牌 |
| `Cors__AllowedOrigins__0` | 允许跨域的前端来源；同源部署（nginx 反代 `/api`）时不会被用到 |
| `YunCai__Database__AutoMigrate` | 是否在应用启动时迁移。生产保持 `false`，由 `--migrate-only` 容器负责 |
| `YunCai__Seed__Enabled` | 是否创建初始管理员与默认账套，仅在首次部署时置 `true` |
| `YunCai__Seed__AdminUsername` / `AdminPassword` | 初始管理员；`Seed.Enabled=true` 而口令为空时，生产环境直接启动失败 |
| `YunCai__Networking__TrustForwardedHeaders` | 反向代理后必须为 `true`，否则限流按代理 IP 计数 |
| `YunCai__Networking__HttpsRedirection` / `UseHsts` | TLS 就位后再打开，否则 HTTP 访问会被跳转打断 |
| `YunCai__Logging__File` | 留空只输出到控制台（容器由 `docker logs` / 日志驱动收集）；要落盘请给绝对路径 |

优先级：`appsettings.json` < `appsettings.{环境}.json` < `appsettings.Local.json` < 环境变量。

## 四、TLS

当前 `deploy/nginx.conf` 只监听 80。上证书后：

1. 证书目录挂载进 `web` 容器，nginx 增加 443 server 块并把 80 改为 301 跳转；
2. `.env` 里 `YUNCAI_HTTPS_REDIRECT=true`、`YUNCAI_USE_HSTS=true`、`YUNCAI_PUBLIC_ORIGIN=https://你的域名`；
3. `docker compose up -d web`。

nginx 已透传 `X-Forwarded-Proto`，后端据此判断是否已在 HTTPS 上，不会形成跳转循环。

## 五、备份与恢复

```bash
# 备份（建议 crontab 每日执行并转存到对象存储）
docker compose exec -T db pg_dump -U yuncai yuncai | gzip > yuncai-$(date +%F).sql.gz
# 恢复
gunzip -c yuncai-2026-10-12.sql.gz | docker compose exec -T db psql -U yuncai -d yuncai
```

数据都在 `pgdata` 卷里，`docker compose down` 不会删除，`down -v` 会——别在生产的机器上用 `-v`。

## 六、日志与排障

```bash
docker compose logs -f api        # 请求日志（UseSerilogRequestLogging）+ 异常堆栈（Problem Details 的 detail 不返回堆栈，堆栈只进日志）
docker compose ps                 # migrate 是否成功退出（exit 0）
```

- 未捕获异常统一返回 RFC7807 Problem Details：业务校验类 400 带中文说明，其余 500 只回「服务器处理请求时发生错误」。
- 登录接口按来源 IP 限流：每 5 分钟 10 次，超出返回 429。
- `/health` 检查数据库连通性，可作为外部探活与负载均衡依据。

## 七、已知边界（上线前需知晓）

- **无用户↔账套授权与角色权限**：任何登录用户对其可见账套都有完整读写权，当前只适合单人/可信内部使用。补齐方案见功能差距清单 P0「多用户与权限」。
- **上传体积上限 32MB**（`deploy/nginx.conf` 的 `client_max_body_size`），电子档案附件以 Base64 存库，账套多了会显著膨胀数据库。
- **列表接口全量返回**：凭证、日记账在服务端没有分页，单期数据量大时首屏会明显变慢。
- 前端单包约 1.4MB（gzip 365KB），尚未做路由级分包。

## 八、本机开发

```bash
cp src/YunCai/appsettings.Local.example.json src/YunCai/appsettings.Local.json   # 填本机数据库与随机 Jwt:Key
cd src/YunCai ; dotnet run            # http://localhost:5271，开发环境自动迁移 + 播种 admin/admin123
cd ui ; npm run dev                   # http://localhost:5173，/api 代理到 5271
```

`dotnet build` 报 MSB3021/MSB3027（`YunCai.exe` 被占用）说明有开发服务在跑：
`Stop-Process -Name云财-Force` 后重新构建。
