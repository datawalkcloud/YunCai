# 税局取数：直连接口与页面路径

服务端用 Playwright 保持税局登录态，所有取数都在**已登录页面里**发出请求。匿名从后端另发 HTTP 会被瑞数 WAF 拦截，所以本文所说的「直连」= 页面内 `fetch` / `XMLHttpRequest`，不是后端直接调税局域名。

> **先回答「是不是返回整页 HTML」这个问题：不是。**
> 数字账户（`/szc/...`）、发票（`/szzhzz/qlfpcx`）、门户待办（`/mhzx/api`）都是 XHR + JSON；个税站（`etax.chinatax.gov.cn/web/...`、`znhd.../jztsController/...`）同样是 XHR，只是响应被整包加密成一个字段。
> 抓到 HTML 只有两种可能：**瑞数的挑战页**（`<!DOCTYPE html>` + `$_ts` 引导脚本 + 随机路径的 `.js`，`<body>` 是空的），或者抓到的是 **SPA 的导航文档本身**（`/skzx/view/skzs/jkkp`、`cddz=/sbzx/view/...` 这类前端路由）。两者都不是数据通道。
> 也就是说：某个功能「拿不到 JSON」不等于「它只有 HTML 页面」，先按下面四种形态分清是哪一种，再决定往哪边调查。

## 响应不是 JSON 时的四种形态

`JsonResponseCollector.ReadAsync` 只把首字符是 `{` / `[` 的响应交给解析器，其余全部按形态留证（`[税局取数] 非 JSON 响应 {Status} {Url} 头部=…`，见 `TaxPortalService.cs:5961-5975`）。四种形态的判法与含义：

| 形态 | 报文长这样 | 含义 | 该做什么 |
| --- | --- | --- | --- |
| ① 明文业务 JSON | `{"Response":{"RequestId":…,"Data":{"PageNumber":1,"PageSize":10,"Total":0,"List":[]}}}` | 通道正常，只是没数据 | 调区间/条件重取，不要动解析器 |
| ② 网关拒绝信封 | HTTP 200 + `{"msg":"会话失效，请重新登录！","code":"9999"}` | **合法 JSON、不是 HTML**；数字账户子系统不认这次调用的来源 | 补建子系统会话（先把页面落到对应 `/szzh/...` 业务页）；反复 9999 说明缺的不只是会话，见「待调查 A」 |
| ③ 整包密文 | 个税站：`dmnHafHu=0Dl8CkqlqWx…`（单个表单字段）；znhd 集中台账：`{"Jmbw":"a01c6X704OMu…"}` | **也不是 HTML**：请求照样是 XHR，只是响应被整包加密，页面自己解密后才画表格 | 网络层拿不到明文，只能读渲染表格（`TaxPortalPageScripts.cs:944-952`）或 tap 页面解密后的 `JSON.parse`（`IitPlainHook`），见「待调查 C」 |
| ④ 整页 HTML | `<!DOCTYPE html …>`，头部有 `$_ts=window['$_ts']`、`<meta id="随机" content="随机" r='m'>`、`/随机段/随机.786fba6.js` | 瑞数挑战页：它的作用是让浏览器算出 Cookie 再自动重载，不含任何业务数据 | 不是「这个功能只有 HTML」，而是**请求没带上页面钩子加的签名**——发得太早、或发在了不带钩子的 frame。等初始化后重试 / 换 frame |

形态 ④ 的实况样本留在仓库根目录 `its_home.html`（2007 字节，`<body>` 为空）；代码里两处「刚落到业务页时前端还在初始化，头一两次请求可能抛 Failed to fetch 或**回 HTML**」的重试逻辑（`TaxPortalService.cs:560-581`、`TaxPortalService.cs:1190-1211`）就是在躲这一型；个税站「首屏也可能先回一个 404 挑战页再自动重载」同理（`TaxPortalService.cs:138-143`）。

## 个税四页：每张表格的列从哪来

「个税申报」下四个页签的数据源分三种：**自然人电子税务局（ITS）**、**本系统工资模块**、**前端自己算的常量列**。ITS 的地址是 `IitHomeUrl = "https://etax.chinatax.gov.cn/"`（`TaxPortalService.cs:1309`），与企业电子税务局（`etax.zhejiang.chinatax.gov.cn:8443/szc/...`）是两套域名、两套登录态（前者的登录族是 `/iit/login*`）。

判据先说结论：**ITS 的表还没有一张是直连**。四份日志（`_iit-verify-api.log`、`_run_employee.log`、`.scratch/api-task-clean.log`、`.scratch/api-drag-human.log`）里出现过的 `web/dkdj/...` 端点共 18 个（业务数据类 10 个），作为明文 JSON 被抓到的次数是 **0**，全部是形态 ③（`[税局取数] 非 JSON 响应 200 … 头部=dmnHafHu=…`）；`[个税取数·接口]` 那几行打出来的 URL 只有 `…/withholding/index.html#/…#table` 这种形状——那是读渲染表格生成的伪报文，不是接口。所以解析器的键只能是税局的中文列名（`IitFilingPayloadParser.cs:6-13`），各省叫法不同就靠候选列名表兜。这只说明**网络层**没有明文：密文是页面自己解的，2026-11-04 起取数已经在它解密之后加了一道 `JSON.parse` tap（见「待调查 C」）。

### 一次 ITS 取数是怎么发出去的

统一走 `FetchIitAsync`（`TaxPortalService.cs:2173-2274`）：取会话 → `IitLoggedOutAsync` 判有没有被踢回登录页 → `InstallIitPlainHookAsync` 装明文抓手（`TaxPortalService.cs:2920`）→ 挂 `JsonResponseCollector` → `drive` 点菜单 → 三路报文（钩子收到的明文 `TakeIitPlainAsync` + 网络层 JSON + `ReadRenderedTablesAsync` 读到的表格行）合并后一起交给解析器（`TaxPortalService.cs:2211-2223`）。

点菜单固定六步（`DriveToIitMenuAsync`，`TaxPortalService.cs:2674-2752`），每步都往 `steps` 里写一条 `ok/miss`，取不到数据时日志能直接看出卡在哪一步：

1. 点「单位办税」——实测会**另开一个标签页**（`/withholding/` 扣缴申报工作台），所以要先等工作台出现再切过去。
2. 点「我知道了」关掉首次进工作台的「WEB端扣缴功能使用须知」，不关下面谁都点不到。
3. 在扣缴义务人列表里点本公司那一行，再点「确定」。
4. 点顶部导航「扣缴申报」把左侧 `el-menu` 展开（菜单条目此刻可能还是隐藏的，点不开也不拦下一步）。
5. 点目标菜单（人员页「人员信息采集」／扣除页「专项附加扣除信息采集」，退路「专项附加扣除」／申报记录页「单位申报记录查询」——必须用全名，工作台里另有「集中申报 → 申报记录查询」，那是按个人查的，本单位永远 0 条）。
6. 菜单页只画表格框架，实测一个请求都不发：工具栏那颗「查询」是筛选面板的开关（点完变成「收起」），面板里那颗才真正发列表请求，所以两步走。

人员页在第 6 步后还有一段：`RevealIitPlaintextAsync`（`TaxPortalService.cs:2392`）等表格真的画出来，数页面上还剩几串打星号的证件号，有就点「明文」开关——开关后面挂阿里云滑块，沿用登录那套拟人拖动，拖完星号还在就补点一次「查询」。

### 实测到的 ITS 页面结构（日志里 `[个税取数] 未解析出数据` 那两条 WRN 全量诊断）

这两行把当时的页面菜单、表头、筛选项和请求路径整条打了出来，是个税侧唯一的结构证据：

### A. 未申报查询：接口是明文 JSON，但我们被 9999 拒（最该先做的）

2026-11-04 在账套「杭州数从科技有限公司」的一次探测（`probe_undeclared.json`，50 条实况报文）里同时看到两件事：

- 页面自己发的 `POST /szc/szzh/sjswszzh/zhcx/v1/DescribeQnsbwcx`，请求体 `{"nsqx":"","pageNum":1,"pageSize":10,"sbqxq":"","sbqxz":"","skssqq":"","skssqz":"","zsdlfs":"","zspm":"","zsxm":""}`，响应**明文** `{"Response":{…,"Data":{"PageNumber":1,"PageSize":10,"Total":0,"List":[]}}}`——通道和字段都确认了。
- 我们侧对同一个地址：早前一次服务内探测按四种过滤条件（无过滤 / 申报期限区间 / 所属期区间 / 按年纳税期限）各发一次，四次全是形态 ② 的 `{"msg":"会话失效，请重新登录！","code":"9999"}`（`probe_qn.txt`）。现行 `ProbeUndeclaredAsync` 的做法是在业务页里带 / 不带 `X-Client-ID` 各发一轮、间隔重试 3 轮，并把响应首 900 字符回传，便于复核。

所以「未申报只能读 HTML 页面」这个假设**已被证伪**，差的是请求本身的某个条件。候选，按排查成本排序：

1. **请求头**：页面那层除了瑞数签名，可能还带了业务头（如应用码 / 来源标识一类）。做法：在页面里给 `XMLHttpRequest` 再包一层（沿用取票钩子的思路），把页面自己那次调用 setRequestHeader 的全套键值打出来，与我们在页面内手写的那几个头逐条比。
2. **发请求的 frame**：`FindPortalFrame` 按 host 挑第一个匹配帧，挑到的可能不是业务 iframe，签名钩子只挂在业务帧上（`FindPortalFrame`，`TaxPortalService.cs:3113`）。做法：探测时把每个帧都发一遍并回传「帧地址 → 响应首 80 字符」。
3. **时机**：`probe_undeclared.json` 的时间线里，`DescribeQnsbwcx` 之前页面刚走过 `znhd/sso/ssoLogin`、`tpass/…/verifyLogin`（登录态在漂）。做法：等页面自己那次查询成功之后再发，比较结果。
4. **换数据源**：门户「我的待办」接口 `/mhzx/api/mh/wddb/v1/wddbquerybbsmxx` 明文回 `Data.wsbxxGrid[]`，实测一行是残疾人就业保障金申报：`gnmc/sbb=残疾人就业保障金申报`、`skssqq=2025-01-01`、`skssqz=2025-12-31`、`sbqx=2026-09-30`、`nssbrq=2026-09-14`、`zt=已申报`、`ztBm=03`、`cddz=/sbzx/view/sdsfsgjssb/#/yyzx/cbj`、`ysbtjuuid`，另有汇总 `wsbsl=1`、`yqwsbsl=0`、`tbsl=0`、`dbt=N`。注意 `zt` 是状态列，`wsbxxGrid` 里**也出现「已申报」行**，口径与「未申报查询」不同，别当同一份数据用。它的请求体没被抓到——`ApiRequests` 的路径白名单只有 `/szc/`、`/szhz/`、`/qlfpcx/`、`/hdjl/`（`TaxPortalService.cs:5550-5553`），`/mhzx/` 被漏掉，先补白名单再摸。

### C. 个税四项：整包密文，不是 HTML——明文在页面解密之后 tap

`etax.chinatax.gov.cn/web/...` 与 `znhd.zhejiang.chinatax.gov.cn:8443/znhd/nsfwsvr/znhdth/jztsController/...` 的响应实测一律是形态 ③（`_iit-verify-api.log`、`_run_employee.log` 里成片的 `非 JSON 200 … 头部=dmnHafHu=…`：`/web/zrr/jbxx/query`、`/web/common/basecode/…`、`/web/zh/login/zhmmdl` 等）。**请求本身仍是 XHR，数据也在响应里，只是整包加密**，所以不存在「个税只给 HTML」。

按端点统计过一遍（就是上面「ITS 端点清单」那 18 个）：作为明文 JSON 进 `[个税取数·接口]` 的次数是 **0**，`web/dkdj/*` 全部只在 `非 JSON 响应 … 头部=dmnHafHu=` 里出现。这只证明**网络层**看不到明文，不证明明文拿不到——`dmnHafHu=` 是页面自己那层加解密的产物，解密动作就发生在这个 JS 上下文里，所以钩子挂在 `XMLHttpRequest` 外层只能看到密文。

同一批抓包里能看到密钥交换链路：`/znhd/cssSecurity/v1/getPublicKey`（POST）回 `{ruuid, security-token-key, tokenKey, sign, publicKey, securityrate}`，`/znhd/sso/ssoLogin`（POST）回明文 `{"Message":"OK","Data":{"userInfo":{…}}}`（字段值单独加密），`/znhd/ticket/isLogin` 回 `{code:200,data:{isLogin:true}}`；znhd 的 `/znhd/nsfwsvr/admin/dict/findPage.json`（POST）更是完全明文。也就是说**加密是按控制器分的**，不是全站密文。

三条路，成本差很多：

- **读渲染表格（一直在用的保底）**：页面驱动查询 → 读它自己解密后渲染的 el-table（`IitTable`）。代价：依赖 DOM 结构、翻页靠点、慢。
- **页面内 tap 明文（2026-11-04 新接，不碰密码学）**：页面画表格之前必然已经把密文解成明文再 `JSON.parse`，所以在 `JSON.parse` 外面包一层就能拿到解密后的报文，同时给 XHR / fetch 标上「最近完成的请求地址」把明文对回接口。实现：`TaxPortalPageScripts.IitPlainHook`（装钩子，缓冲最近 12 份 ≥120 字节的 JSON 文本）、`IitPlainTake(fragment)`（按接口片段取正文）、`IitCryptoRecon`（摸底它自己的加解密落在哪个全局对象 / 同源脚本 / webpack 模块）。`InstallIitPlainHookAsync` 同时注册为**上下文级初始化脚本**（覆盖「单位办税」那张新标签页）并在现有帧上即时评估一次；`FetchIitAsync` 的报文来源因此变成三路：明文钩子 → 网络层恰好明文的少数接口 → 渲染表格。拿到的就是普通 JSON，现有 `IitPayloadReader` 那套「候选字段名取值」直接能吃，不需要新增解析器。
- **合成加密请求（下一步）**：真解到明文之后，`IitCryptoRecon` 的回包里若指出 encrypt/decrypt 挂在某个全局或 webpack 模块 id 上，就可以在页面内**调用它自己的函数**加密一个自定义 `pageNum` / `pageSize` 的请求体再发出去——等于把「采集重发」搬到密文侧，仍然不用在后端复刻 RSA/AES。这一步取决于 recon 的实际输出，还没写。

诊断端点：`POST /api/TaxPortal/{账套}/debug/iit-plain`（body 可选 `{"menu":"单位申报记录查询"}`，缺省「人员信息采集」）。它会点到目标菜单、装钩子、**再点一次「查询」**，然后回 `{url, target, steps, hooked, plain, recon}`——`plain` 是各帧钩子缓冲的概况（`parseCalls` / `big` / 每份的 `url`、`len`、`count`、`keys`、正文前 900 字），`recon` 是加解密摸底结果。PowerShell：

### D. 税费种 / 申报：直连只在浙江

`FetchTaxKindsDirectAsync` 对非 `zhejiang` 域名直接返回 null 走菜单（`TaxPortalService.cs:533-537`）。其他省是「没验过」，不是「验过只能读页面」——要接外省时先跑一次 `probe-undeclared` 同形态的探测，把该省的 `Describe*` 地址与请求头摸出来再下结论。

### E. 一键取票：钩子失效分支未实测

采集重发的判据是钩子记录的请求体里有没有 `Jmbw`（`TaxPortalService.cs:3936-3947`）。本机账套 2025-10~2026-10 税局返回 0 张发票，「只拿到密文」「翻页未取满」这两个分支从来没被真实数据触发过；等有多页发票的账套出现时才能确认兜底是否够用。

## 前置条件

- **数字账户子系统会话**：税费种、申报、缴款与完税证明接口挂在数字账户下，税局网关对没进过该子系统的会话回形态 ②（`9999`）。服务会先把页面落到对应的 `/szzh/...` 业务页（`?ruuid=` 触发前端重新初始化），子系统会话由页面加载时自己种下；仍被拒时重开一次业务页再取。
- **浙江限定**：目前只有浙江的数字账户接口验证过。非浙江域名下，税费种走菜单；缴款信息与已开具完税证明直接返回「目前只接入了浙江电子税务局」的提示；申报接口同样只在浙江环境实测。
- **WAF 加密**：页面加载后瑞数会改写 `XMLHttpRequest` / `fetch`，请求体变 `Jmbw`、URL 加随机签名。取票的请求钩子挂在它外层，因此捕获到的是明文；重发仍走页面 XHR，由瑞数重新加密和签名。不需要在后端复刻 RSA / tokenKey / sign。
- **登录态**：内存会话按 `(账套, 用户, 税局/个税)` 保存，30 分钟空闲回收；加密的 Playwright storage state 存在数据库，服务重启后 `Resume` 恢复，恢复不了才让用户重新收短信。

## 已验证明文接口：缴款信息 / 完税证明

两份模板均从页面真实请求的 `PostData` 抓取（明文，未经 `Jmbw` 加密），并在已登录的数字账户页面内用 `fetch` 按自定义区间重放验证通过；服务已按此接入。

### 缴款信息 `DescribeJkxxcx`

```
POST https://etax.zhejiang.chinatax.gov.cn:8443/szc/szzh/sjswszzh/zhcx/jkxx/v1/DescribeJkxxcx
Content-Type: application/json

{"jkrqq":"2025-10-01","jkrqz":"2026-11-03","skssqq":"","skssqz":"",
 "skzlDm":"","zspmDm":"","zsxmDm":"","pageNum":1,"pageSize":500}
```

- `jkrqq` / `jkrqz`：缴款日期起止；`skssqq` / `skssqz`：税款所属期起止；`skzlDm` / `zspmDm` / `zsxmDm`：税款种类 / 征收品目 / 征收项目过滤，空串表示不限。

- 实测：`pageSize=500` 一次取回，区间 `2025-10-01` ~ `2026-11-03` 返回 `Total=1`（印花税 2.51，电子缴款书号 `333016260100314673`）；把区间改为 `2026-02-01` ~ `2026-02-28` 返回 `Total=0`，确认 `jkrqq` / `jkrqz` 生效。

### 页面填日期的已知问题

缴款信息与完税证明页面的日期区间输入框在无头浏览器里定位不到（早期日志 `区间框=miss`）。现在服务不再填页面表单，直接调上面两个接口，日期区间由请求体控制。

## 失败与兜底约定

- 直连只读，任何一步不符合预期都返回 `NeedLogin` / 诊断信息，不向前端抛异常；缴费、开票等写操作仍引导用户到电子税务局办理。
- 关键日志：`[税局取数] 税费种接口直连拿不到 JSON，改用菜单路径`、`[税局取票] 页面钩子只拿到加密报文…`、`[税局取票] 直连接口取回 N 张发票…`、`[个税取数·接口]`、`[税局取数] …接口第 N 次调用失败`。
- 申报接口只认小写 `pageSize`，且 `pageNumber` 不生效，只能整年一次取回；翻页上限见 `MaxReportWindows`。缴款信息与已开具完税证明接口的 `pageNum` 生效，按 `Total` 翻页。
